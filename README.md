# 蔵書管理（GitHub Pages + ローカル登録ツール）

離れた場所（本屋など）から「この本を持っているか」を確認できるようにし、あわせて研究室・学科の学生や他大学の研究仲間に向けた「選書リスト」として蔵書を公開するためのツールです。

## 全体の仕組み

- **登録・タグ付け**: PCで動かすローカル専用ツール（`admin/`）。バーコードリーダーでのISBN読み取り、またはISBNのない本の手入力に対応。書誌情報（タイトル・著者・発行年）はopenBD / Google Booksから自動取得。
- **データ本体**: [data/books.json](data/books.json)。ローカルツールで登録するとこのファイルが更新される。
- **公開・共有**: GitHub Pages（[index.html](index.html)）。`data/books.json` を読み込んで、検索・タグ絞り込みができる一覧として誰でも閲覧できる（読み取り専用、編集機能なし）。
- **反映のタイミング**: 登録作業をまとめて行った後、ローカルツールの「Gitに反映」ボタン（またはターミナルでの`git push`）でGitHubに反映する、というまとめ更新のスタイル。リアルタイム同期はしない。

```
index.html          ← 公開ページ（GitHub Pagesで表示される）
css/style.css        ← 共通スタイル
css/public.css        ← 公開ページ用スタイル
js/app.js              ← 公開ページのロジック（検索・タグ絞り込み・並び替え）
data/books.json         ← 蔵書データ本体

admin/                  ← ローカル専用（登録・タグ編集用、外部には公開しない）
  server.js              ← Node標準機能のみで書かれたローカルサーバー
  index.html              ← 登録・タグ編集画面
  admin.js
  admin.css
  lookup.js               ← ISBN→書誌情報取得（openBD + Google Books）
```

## 必要な書誌情報

タイトル・著者・発行年・ISBN（任意）の4項目のみ。ISBNのない本（古い本や非売品など）も手入力で登録できる。タグは自由入力（カンマ区切り）で、複数付けられる。

## 使い方（登録側・PC）

1. Node.jsが入っていればOK（バージョン確認: `node -v`）。
2. ターミナルでこのフォルダに移動し、次を実行してローカル登録サーバーを起動する。

   ```bash
   node admin/server.js
   ```

3. ブラウザで `http://127.0.0.1:8787` を開く。
4. バーコードスキャナ接続時は、ISBN欄にカーソルを合わせてスキャンするだけで自動検索される（スキャナは自動でEnterを送るキーボード入力として動作する）。ISBNのない本は「ISBNなしで手入力登録」から直接入力する。
5. 内容を確認し、必要ならタグを追加して登録。登録済みの本のタグ編集・修正・削除も同じ画面の一覧からできる。
6. 作業がひと段落したら、画面右上の「⬆️ Gitに反映（commit & push）」ボタンを押す。`data/books.json` の変更が自動でcommit・pushされる（このボタンは内部で `git add` → `git commit` → `git push` を実行しているだけなので、ターミナルから同じコマンドを打っても同じ結果になる）。

このローカルサーバーは `127.0.0.1`（自分のPCから）のみで待ち受けており、外部からはアクセスできない。バーコードリーダーを使わない小さな図書室のような使い方であれば、そのまま複数冊まとめて登録してからまとめてpushする運用で問題ない。

## 公開側（GitHub Pages）のセットアップ

1. GitHubにリポジトリを作成し、このフォルダ一式をpushする。

   ```bash
   git init
   git add .
   git commit -m "初期コミット"
   git branch -M main
   git remote add origin https://github.com/あなたのユーザー名/リポジトリ名.git
   git push -u origin main
   ```

2. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、Branch を `main` / `/(root)` にしてSave。
3. 数分後 `https://あなたのユーザー名.github.io/リポジトリ名/` で公開される。GitHub Pagesは自動でHTTPS化される。
4. [index.html](index.html) 冒頭の紹介文（`<p class="intro">`）は、公開の目的や対象読者に合わせて自由に書き換えてよい。

以降は、ローカルで登録 → 「Gitに反映」ボタン（またはgit push）→ 数分待つと公開ページに反映、という流れになる。

## 制限事項

- リポジトリを公開設定にすると、蔵書データ（タイトル・著者・発行年・ISBN・タグ）とコミット履歴が誰でも見られる状態になる。今回は「選書リストとして公開してよい」という前提で設計している。
- 複数のPCから登録する場合は、それぞれで `git pull` してから登録・pushする運用にしないと、データが古い状態を上書きしてしまう可能性がある（現状は1台のPCでの運用を想定したシンプルな作り）。
